# 第四步交接：对抗训练（尚未开始）

当前代码已经完成原模型基线和 FGSM/PGD 评估。此文是下一阶段计划，不代表训练已经执行，也没有现成的训练入口命令或训练检查点。

## 更强设备上的准备

1. 克隆仓库，阅读根目录 `AGENTS.md`、`HANDOFF.md` 与 `docs/baseline_and_attacks.md`。
2. 使用 Python 3.12，安装与设备匹配的官方 PyTorch GPU 包，再安装依赖。`requirements-lock.txt` 是本机 Windows/CUDA 12.8 的实际环境快照，不应强行用于不同平台；变更版本后记录新环境。
3. 使用已提交的 `splits/train.csv` 与 `splits/validation.csv`，保持 seed=5577。两个文件都指向 `data/dataset3/train_images/`。不需要在每次训练时重新划分或扫描全部图片。
4. 执行测试与环境检查。更换 GPU 后计时和显存不同是正常现象；跨硬件不承诺浮点结果逐位一致。

## 建议的实验顺序

先实现一个清楚的训练入口，支持记录配置、训练/验证日志、保存最佳与最后检查点，并支持包含优化器、调度器、epoch 和随机数状态的恢复训练。

| 候选 | 初始化 | 训练输入 | 用途 |
|---|---|---|---|
| Clean fine-tuning | 课程权重 | 干净训练图片 | 判断仅继续训练带来的变化 |
| FGSM adversarial training | 同一课程权重 | 干净 + FGSM | 成本较低的对抗训练对照 |
| PGD adversarial training | 同一课程权重 | 干净 + PGD | 主要防御候选 |
| From-scratch comparison | 随机初始化 | 干净或对抗训练图片 | 获得真正排除验证 ID 的本地比较 |

初始探索设置可以从 batch=64、epsilon=8/255、PGD step_size=2/255、7–10 步开始。它们是待测起点，不是已证实最佳参数。根据新设备的实测显存和速度调整批大小，并完整记录。先完成一个短训练试跑，再投入完整训练，避免在数据加载或梯度模式错误时浪费算力。

## 训练实现重点

- 数据增强只用于训练，保持验证确定性。规范化仅由 ProvidedNet 内部执行。
- 生成攻击时需要输入梯度；外层模型更新需要模型参数梯度。当前 `common.load_provided_model()` 为评估冻结了参数，训练入口必须显式恢复 `requires_grad_(True)`，不能直接沿用冻结状态。
- `attacks.pgd()` 当前用于**评估**：优先保留成功误分类，再比较交叉熵。训练的内层最大化交叉熵与该优先级不是完全相同目标。训练时明确实现/选择最大 CE 候选或约定的最后迭代，说明选择依据，不要无说明地混用。
- 生成攻击时使用 eval 模式，避免 BatchNorm 统计被内层多步更新、Dropout 引入随机变化。外层训练恢复 train 模式；记录这种约定。
- 损失可以先采用干净 CE 与对抗 CE 的加权和，权重属于需要验证的超参数。选择模型时同时关注干净与受攻击表现。
- 不引入外部数据和预训练权重；禁止将现成攻击/防御包作为黑盒替代本项目算法实现。

## 评估与验收

- 对相同验证 ID 报告干净、FGSM、PGD、多重随机起点及固定 50% 攻击混合集的 Macro-F1。混合集分数应重新计算，不能平均两个 F1。
- 区分针对课程模型生成后迁移到防御模型的攻击，与直接针对防御模型的攻击。
- 训练参数选择不能只依赖 FGSM，应保留更强 PGD 检验。强攻击下分数更高时应检查实现/梯度，而不是立即宣称更鲁棒。
- 课程权重及其微调后代已经见过全部原始训练数据，因此其本地验证仍为 diagnostic。随机初始化候选在模型选择时只用 7,575 张训练数据。
- 最终记录真实防御前后 Kaggle Public 分数、训练/推理耗时、显存、模型选择和失败案例。真实防御前 Kaggle Public 基线已取得：**0.51194**，证据见 `results/kaggle_baseline_public_score.png`；防御后分数尚未取得。
